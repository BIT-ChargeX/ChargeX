# 需求 #14 — 用户账号管理

| 属性 | 内容 |
|------|------|
| 所属子系统 | PC 服务器端 |
| 需求类别 | 管理需求 |
| 开发技术 | C++ / Qt Creator / SQLite |

## 功能描述

管理员在后台主界面进入用户管理模块，可执行三类操作：查看用户列表、手机号模糊搜索、账号冻结/解冻。

### ① 查看用户列表

系统从数据库读取所有注册用户，以表格形式展示：用户 ID、手机号（脱敏显示中间四位，如 `138****5678`）、昵称、钱包余额（元，保留 2 位小数）、注册时间（`yyyy-MM-dd HH:mm:ss`）、账号状态（正常 / 冻结）。默认按注册时间倒序排列，最新用户置顶。

### ② 手机号模糊搜索

管理员在搜索框输入手机号关键词（可为部分号码），系统执行 `LIKE '%keyword%'` 模糊查询并实时刷新表格。清空搜索框后自动恢复展示全量用户列表。若无匹配结果，表格显示"暂无符合条件的用户"。

### ③ 冻结 / 解冻账号

管理员选中用户行后，根据当前状态显示"冻结"或"解冻"按钮，操作前弹出确认对话框。

- **冻结**：将目标用户 `status` 字段更新为 `0`。被冻结用户在充电用户端登录时收到提示"您的账号已被冻结，如有疑问请联系客服"，无法进行任何充电操作
- **解冻**：将 `status` 恢复为 `1`，用户可重新登录并使用全部功能

## 前置条件

1. 管理员已完成登录（需求 #11），持有有效会话
2. 数据库 `users` 表已存在并包含至少一条记录

## 输入

1. 搜索关键词（手机号，可为空；空时展示全部）
2. 目标用户 ID（行选中后操作时）
3. 操作类型（冻结 `status=0` / 解冻 `status=1`）

## 输出

1. 用户列表表格（含 ID / 手机号 / 昵称 / 余额 / 注册时间 / 状态）
2. 搜索结果实时刷新
3. 冻结/解冻操作成功提示 + 对应行状态即时更新

## 异常情况处理

| 异常场景 | 处理方式 |
|----------|----------|
| 对已冻结账号再次冻结 | 按钮置灰不可点击；强制触发时提示"该用户已处于冻结状态"，不发起数据库更新 |
| 未选中用户行时点击操作 | 提示"请先选择要操作的用户"，不执行任何操作 |
| 数据库更新失败 | 界面保持原状态，弹窗提示"操作失败，请稍后重试" |
| 用户列表加载失败 | 显示错误状态区域，提示"数据加载失败，请刷新重试"并提供刷新按钮 |

## UML 时序图

![需求16 UML时序图](16.png)

本需求包含三条时序流程：
1. **流程 1** — 查看用户列表（打开界面 → 请求全量数据 → 表格展示）
2. **流程 2** — 手机号模糊搜索（输入关键词 → LIKE 查询 → 结果刷新 / 无结果提示）
3. **流程 3** — 冻结/解冻账号（选中行 → 确认对话框 → UPDATE 操作 → 结果反馈）

### 时序图参与者说明

| 参与者 | 说明 |
|--------|------|
| 管理员 | 操作 PC 服务器端后台的人员 |
| Qt客户端界面 | PC 服务器端的 Qt 图形界面层，负责表格展示与用户交互 |
| 业务处理模块 | 核心逻辑层，处理查询条件拼装、状态校验与操作执行 |
| 数据库 | SQLite 数据库，存储用户账号与状态信息 |
